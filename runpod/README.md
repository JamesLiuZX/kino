# Running Kino's models on RunPod

Kino sends every model app to a ComfyUI 0.41 server as an API-format workflow.
There are two ways to give it one. Both use the same model files, fetched by
`download-models.sh`.

| | GPU pod + ComfyUI | Serverless endpoint |
|---|---|---|
| You pay | Per hour while the pod is on | Per second while a job runs |
| Cold start | None once the pod is up | 1–3 min when no worker is warm |
| Live progress | Step by step | Estimated |
| Big inputs (long videos) | No limit | 10 MB of inputs per job |
| Best for | A working session, iterating fast | Leaving the studio on, occasional use |

**GPU size.** A 48 GB card (L40S, RTX 6000 Ada, A6000) runs every app. 24 GB
(RTX 4090, L4, A5000) runs Fast image, Draft video, Upscale and Smooth.
Blackwell cards (RTX 5090, RTX PRO 6000, B200) run the NVFP4- and
INT8-quantized MiniMax H3 and Qwen models fastest; older cards dequantize them
on the fly, which works but is slower.

## Option A: a GPU pod running ComfyUI

1. RunPod → **Pods → Deploy**. Pick a 48 GB GPU and a ComfyUI template that
   ships **ComfyUI 0.41 or newer**. Give it a volume of about 200 GB (step 2's
   dry run prints the exact total for the apps you pick).
   (On an older template, update first: `cd /workspace/ComfyUI && git pull &&
   pip install -r requirements.txt`, then restart ComfyUI.)
2. Open the pod's web terminal and fetch the models for the apps you want:

   ```bash
   git clone --depth 1 https://github.com/JamesLiuZX/kino /tmp/kino-src
   cd /tmp/kino-src/runpod
   bash download-models.sh --dry-run image-fast video-pro edit   # sizes, free space
   bash download-models.sh image-fast video-pro edit
   ```

   On a ComfyUI pod the files land in `/workspace/ComfyUI/models`. Restart
   ComfyUI (or press **Refresh** in its UI) so it sees them.
3. Pod → **Connect → HTTP 8188**: copy the link
   (`https://<pod-id>-8188.proxy.runpod.net`).
4. Kino → **Settings → ComfyUI server**, paste the link, **Save and test**. The
   test lists which apps have all their models.

Stop the pod when you're done; the volume keeps the models for next time.

## Option B: Serverless (pay per second)

1. **Network volume.** RunPod → **Storage → New Network Volume**, in a data
   centre that has your GPU type. Start around 200 GB; `download-models.sh
   --dry-run <apps>` (step 2) prints the exact total, and volumes can grow later.
2. **Fill it.** Deploy any cheap pod *with that volume attached* (it mounts at
   `/workspace`), then in its terminal:

   ```bash
   git clone --depth 1 https://github.com/JamesLiuZX/kino /tmp/kino-src
   bash /tmp/kino-src/runpod/download-models.sh image-fast video-pro edit cutout
   ```

   Files go to `/workspace/models/...`, which Serverless workers see as
   `/runpod-volume/models/...`. Terminate the pod afterwards.
3. **Worker image.** Build and push this folder's Dockerfile (runpod/worker-comfyui
   upgraded to ComfyUI 0.41, with model paths for every folder Kino uses):

   ```bash
   docker build --platform linux/amd64 -t <dockerhub-user>/kino-worker:0.41.0 kino/runpod
   docker push <dockerhub-user>/kino-worker:0.41.0
   ```

   (Or connect the repo in RunPod's GitHub integration and point it at
   `kino/runpod/Dockerfile`.)
4. **Endpoint.** RunPod → **Serverless → New Endpoint**: the image above, the
   network volume, a 48 GB GPU, *Max workers* 1–3, *Idle timeout* 60–120 s
   (keeps a worker warm between generations), *Execution timeout* 900 s.
5. **Test it.** In the endpoint's **Requests** tab, paste `test-input.json` (a
   Fast image workflow) and run it. A cold start downloads nothing but still
   loads the model, so the first run is the slowest.
6. Kino → **Settings → RunPod Serverless**: the endpoint ID and an API key
   (RunPod → Settings → API Keys), **Save and test**.

### When something fails

- *Model file missing* / *not in list*: that app's files aren't on the volume.
  Run `download-models.sh <app>` on a pod with the volume attached.
- *Inputs are too large*: Serverless takes 10 MB per job. Use a shorter clip,
  or a GPU pod (Option A) for video upscaling and smoothing.
- *Workflow didn't validate* / unknown node: the worker runs an older ComfyUI.
  Rebuild from this Dockerfile.

## Files

- `Dockerfile`: the Serverless worker image.
- `extra_model_paths.yaml`: model folders on the network volume.
- `download-models.sh`: fetches the files listed in `models.json`, by app.
- `models.json`: every model file Kino's built-in apps load (generated by
  `scripts/build-workflows.mjs` from the official ComfyUI templates).
- `test-input.json`: a ready-to-run Serverless request.
